# 원칙과 규칙 (단일 원본)

이 파일이 프로젝트 규칙의 **유일한 원본**이다. 다른 문서는 여기를 가리키기만 한다. 규칙을 바꾸려면 이 파일을 고치고, 근거는 `docs/study/`의 노트에 둔다.

상태 표기: **[확정]** 근거 있음 · **[미검증]** 선례 없는 우리 고유 규칙, 직접 측정 예정 · **[가설]** 약한 근거, 게이트에서 의심만

근거 약어: `MP` = study/mattpocock-skills.md · `WK` = study/obsidian-wiki-review.md · `DR` = study/deep-research-similar-cases.md (7절 검증 결과 기준)

## 1. 목적

개발을 돕는 Claude Code 플러그인. 우선순위 순:

1. **개발 품질**
2. **토큰 절약** — 가볍게 동작
3. **일정하고 유용한 산출물**
4. **반복 오류의 자가 보완** — 구조는 §4

## 2. 최상위 규칙: 스킬 채택의 세 게이트 [확정]

모든 스킬은 셋을 **모두** eval로 입증해야 반영한다. 하나라도 미입증이면 백로그.

| 게이트 | 기준 | 조작적 정의 |
|---|---|---|
| **G1 정확한 트리거** | 켜져야 할 때만 켜진다 | should-fire / should-not-fire 약 20개, train/test 분리. 과잉 트리거는 미발동과 같은 실패 |
| **G2 확연한 이득** | 스킬 유/무 비교에서 확연히 낫다 (품질 또는 비용) | **이득과 회귀를 쌍으로 보고.** 기준선 vs 기준선 반복으로 뒤집힘 노이즈 바닥을 먼저 측정. **회귀 ≤ 노이즈 바닥은 필수.** 그 위에서 (a) 품질 Δ가 노이즈 바닥을 넘어 반복에서 일관하면 **품질형 통과**, (b) 품질 Δ가 노이즈 바닥 안(동률)이고 출력 토큰 또는 소요 시간이 측정한 모든 모델에서 확연히 줄면(잠정 기준 30% 이상) **비용형 통과**. 둘 다 아니면 실패. 노이즈 바닥 안의 순Δ는 품질 이득이 아니다. 비용 척도는 출력 토큰·소요 시간이며 컨텍스트 토큰 비율은 턴 수에 비례하므로 참고치로만 둔다. 보고서에 품질형/비용형을 구분해 적는다. 회귀 사례는 하나씩 정성 검토. description만 있고 호출 안 된 조건도 측정(삼투) |
| **G3 과하지 않은 토큰** | 상시 로드 + 실행 비용이 이득에 비해 과하지 않다 | `/skill-doctor`로 측정. 비싸면 **라우팅**: user-invoked 라우터(`disable-model-invocation: true`, description 자체가 로드되지 않음) + 필요 시 읽는 references/ |

**충돌 시 G3 우선.** 자동 발동 일관성을 포기하고 사람이 켜는 라우터로 돌리는 것은 허용. 상시 컨텍스트를 무겁게 하는 것은 불허.

근거: G1 과잉 트리거 사례 `MP §6`. G2 회귀세·삼투 `DR F1·F2·7.3-1·2`(회귀 0 기준은 기각됨, 노이즈 바닥으로 대체). G2 비용형 통과·"순Δ>0" 기준 폐기는 `study/gate-eval-round-1.md` flaky-check 2차(품질 동률 +0.4%에 시간 1/3·출력 토큰 1/2, 2026-10-23 결정). 목적 §1의 2·3(토큰·일정한 산출물)에 기여하는 스킬이 게이트에서 걸리지 않게 하기 위함. G3 description 미로드 `DR F8`. 경량 지지: SkillsBench 집중형 스킬(모듈 3개 이하)이 포괄형보다 나음 `DR 7.2`.

## 3. 설계 규칙

### 3.1 내장 스킬과 겹치지 않고 연동 [확정]
code-review, simplify, security-review, skill-creator 등 내장과 역할이 겹치는 스킬은 만들지 않는다. 설계 전 중복 여부를 먼저 확인하고, 겹치면 호출하거나 결과를 이어받는다. 내장이 하는 분석·제안(`/insights`, `/doctor prompt-audit`, `/skill-doctor`, `claude plugin eval`)과 우리 것 사이의 빈칸만 만든다. 근거: `WK §2`.

### 3.2 배치: 어디에 쓰는가 [확정]
| 내용 | 위치 |
|---|---|
| 모든 분기가 반드시 거치는 짧은 제어 | SKILL.md 본문 인라인 |
| 도메인 지식, 긴 참조, 일부 분기만 쓰는 것 | `references/` (필요 시 로드) |
| 결정적으로 검사 가능한 규칙 | **기존 린터·CI 먼저.** Claude Code 훅은 반복 위반이 관찰되고 거짓양성률을 측정한 뒤에만. 훅에도 G1(거짓양성)·G3(실행 비용) 적용 |
| 결정적 작업(정제, 차분, 파싱) | `scripts/`. LLM을 파서로 쓰지 않는다. 도구 출력은 수십 줄 이내 |
| 비표준 규약, 코드에서 추론 불가한 것, 문서 포인터 | CLAUDE.md (최소) |

"지시로 강제"는 선택지가 아니다. CLAUDE.md·메모리는 context이지 enforced configuration이 아니다. 근거: `WK R1·R7`, `DR F5·F8·7.3-3`(훅은 "층으로 더하라", 프로즈 생략은 기각됨), `DR F11`(사람 평가자는 훅 없는 쪽 선호).

### 3.3 경량 [확정]
스킬 하나는 하나의 일. 상시 로드는 최소. SessionStart에 아무것도 주입하지 않는다. 트리거 강제 훅(매 프롬프트 주입)은 G3를 통과한 경우에만 최후 수단. 근거: `WK R8`, `DR F10·7.3-10`.

### 3.4 파일 상한 [확정, 근거는 토큰]
규칙 파일은 200줄 미만. 근거는 **토큰 비용**이다. "길면 안 따른다"는 사소한 지시 실험에서 길이 효과가 검출되지 않아 **미확인**. 줄마다 "지우면 실수가 생기는가"를 묻고, 정기적으로 `/doctor prompt-audit`. 근거: `DR F4·7.3-4`.

### 3.5 가이드라인성 내용은 스킬로 만들지 않는다 [가설]
"항상 X 해라" 류 가이드라인은 스킬 트리거 eval에서 저조할 가능성이 크다. G1에서 우선 의심한다. 근거 약함(n=15 블로그). `DR F9·7.3-8`.

### 3.6 외부 프로젝트와 프레임워크 [확정]
`.ref/`는 참고만, 복제하지 않는다. Superpowers 자체에 대한 독립 측정은 찾지 못했다. Spec Kit류 파이프라인은 측정된 효과가 작고(+0.15/5점) 경량 방식과의 직접 비교는 없다. "미검증"이라고 쓰지 않는다. 근거: `DR F11·7.3-9`.

## 4. 자가 보완 루프 (목적 4의 구조)

```
[오류 발생] → 이번 오류를 고친다 (루프 우선: red가 되는 명령 없이 가설 금지)
     ↓ 맞은 가설을 커밋 메시지에
[고정 트리거] → 감지: 세션 종료 / Stop 훅에서 관찰 로그에 기록 (자동)
     ↓
[승격 판단] → 2~3회 반복 관찰 후 사람 승인 (자동 적용 없음)
     ↓ 델타만 (추가·카운터 증가), 전면 재작성 금지
[배치] → §3.2 표에 따라 린터·CI → 훅 → 문서 순
     ↓
[감사] → helpful/harmful 카운터. 해로운 규칙 제거. 0적중 규칙은 제거 후보
```

- **4.1 감지는 고정 트리거로** [확정]: 판단 의존 캡처는 미발동(60세션 중 2회), regex 캡처는 오탐(625건 중 적중 0). 근거: `WK R2`.
- **4.2 승격 임계 2~3회 + 사람 승인** [미검증]: 선례 없는 고유 규칙. 자동 적용은 하지 않는다(리뷰형). 근거: `WK R2`, `DR 7.3-6`.
- **4.3 승격은 델타만** [확정, 근거 약함]: 전면 재작성은 컨텍스트 붕괴(n=1 사례). 근거: `DR F7·7.3-7`.
- **4.4 역할 분리** [확정]: 규칙 파일(CLAUDE.md, SKILL.md)은 사람 소유. 에이전트가 쓰는 관찰 로그는 **지시로 로드하지 않는다**(인젝션 영구화 방지). 근거: `WK R3`(Akamai 사례, Anthropic `#` 단축키 제거). ETH 논문을 이 근거로 쓰지 않는다(외삽).
- **4.5 규칙마다 출처 실패 + helpful/harmful 카운터** [확정]: ACE의 직접 선례. "0적중 프루닝"은 **미검증** 고유 규칙. **해로움을 누가 무엇으로 판정하는지 정하지 않으면 카운터는 빈다** — 설계 시 정할 것. 근거: `DR F6·7.3-6`.
- **4.6 루프 우선** [확정]: 오류를 고칠 때 재현 명령이 먼저, 추측은 나중. 근거: `MP §6`.

## 5. eval 실행 규칙 [확정]

- 형식: skill-creator의 `evals/evals.json`. `claude plugin eval`과 비호환이므로 하나만 쓴다.
- 반복: 케이스당 **3회 이상**. 단일 실행 비교 금지. mean±stddev.
- 노이즈 바닥: 기준선 vs 기준선 반복으로 뒤집힘률을 먼저 잰다 (G2 전제).
- 트리거: should/should-not 약 20개, 60/40 train/test. 과적합 방지.
- 비변별 assertion(스킬 유무와 무관하게 통과)은 삭제.
- 증거 필수: 성공 주장이 아니라 테스트 출력·실행 명령·결과. grader에도 evidence.
- 기록: 모델 버전, CLI 버전, 날짜를 eval 로그에 고정.
- 근거: `WK R6`, `DR 7.3-1·11`.

## 6. 프로세스 규칙

- **6.1 리서치 결과를 원칙에 반영하기 전에 1차 출처를 직접 읽는 독립 검증을 거친다** [확정]. 주장 단위 검증은 수치는 잡지만 선별·해석 편향은 못 잡는다. 질문에 전제를 넣지 않는다. 근거: `DR 7.5`.
- **6.2 규칙 변경은 이 파일 한 곳에서** [확정]. 스터디 노트의 "우리에게 적용" 절은 후보일 뿐, 여기 반영되기 전엔 규칙이 아니다.
- **6.3 스킬 채택 체크리스트**: G1·G2·G3 통과 → §3.1 중복 없음 → 목적 1~4 중 하나에 직접 기여 → 반복 사용됨 → 이 파일의 해당 절에 모순 없음.

## 7. 용어

- **루프(red)**: 이 버그·이 스킬 효과에서 실패가 되는 명령 하나. 없으면 검증된 게 아니다.
- **라우터**: 본문이 다른 스킬 호출뿐인 얇은 user-invoked 스킬. 토큰 0.
- **삼투**: 스킬이 호출되지 않아도 description만으로 행동이 바뀌는 현상.
- **노이즈 바닥**: 같은 설정을 반복했을 때 성공/실패가 뒤집히는 비율. 이 아래의 "회귀"는 회귀가 아니다.
- **승격**: 관찰 로그의 항목이 사람 승인을 거쳐 규칙·훅이 되는 것.
