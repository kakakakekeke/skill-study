# 프로젝트 목적과 원칙

## 최상위 규칙: 스킬 채택의 세 게이트

**이 프로젝트에서 가장 중요한 규칙이다.** 모든 스킬은 아래 세 게이트를 **모두** 통과해야 저장소에 반영된다. 하나라도 입증되지 않으면 백로그에 남는다. 다른 모든 원칙은 이 규칙의 하위에 있다.

| 게이트 | 기준 | 입증 방법 |
|---|---|---|
| **1. 정확한 트리거** | 켜져야 할 때 켜지고, 켜지지 말아야 할 때 켜지지 않는다 | 트리거 eval: 긍정 케이스(발동해야 함)와 부정 케이스(발동하면 안 됨)를 모두 두고 정확도를 측정한다. 과잉 트리거는 미발동과 똑같은 실패다 |
| **2. 확연한 품질 향상** | 스킬이 있을 때의 결과가 없을 때보다 **확연히** 좋다 | 품질 eval: 같은 과제를 스킬 유/무로 돌려 비교한다. "조금 나아진 것 같다"는 통과가 아니다. 차이가 보이지 않으면 반영하지 않는다 |
| **3. 과하지 않은 토큰 소모** | 항상 로드되는 분량과 실행 시 소모가 얻는 이득에 비해 과하지 않다 | 기본 로드(description + 항상 읽히는 본문) 측정, 실행 1회 토큰 측정. 비싸면 **라우팅으로 해결**한다: 얇은 user-invoked 라우터 + 필요할 때만 읽는 참조로 나누거나, `disable-model-invocation`으로 상시 비용을 0으로 만든다. 일관되게 자동 발동하지 못하더라도 토큰이 과한 것보다 낫다 |

게이트 3의 보충: 트리거 정확도(게이트 1)와 토큰 비용(게이트 3)이 충돌하면 **토큰을 우선**한다. 자동 발동을 포기하고 사람이 켜는 라우터로 돌리는 것은 허용된 해법이다. 상시 컨텍스트를 무겁게 만드는 것은 허용되지 않는다.

## 목적

개발을 돕는 Claude Code 플러그인을 만든다. 우선순위는 다음 네 가지다.

1. **개발 품질** — 코드와 산출물의 품질을 일정하게 유지한다.
2. **토큰 절약** — 불필요한 컨텍스트 소비를 줄인다. 가볍게 동작해야 한다.
3. **일정하고 유용한 산출물** — 개발자에게 실제로 도움이 되는 결과물을 매번 같은 형태로 낸다.
4. **반복 오류의 자가 보완** — 개발 중 반복적으로 발생하는 오류를 스스로 감지하고 보완하면서 프로젝트를 진행한다.

## 원칙

### 1. eval로 입증된 것만 반영한다
- 모든 스킬은 철저한 eval을 거친다. 효과가 입증되지 않은 지침은 넣지 않는다.
- "있으면 좋을 것 같은" 내용은 백로그에 두고, eval로 효과를 확인한 뒤에만 SKILL.md에 반영한다.
- 트리거 정확도(언제 켜지는가)와 품질(켜졌을 때 결과가 좋은가)을 분리해서 측정한다.

### 2. Anthropic 내장 스킬과 겹치지 않고 연동한다
- Claude Code에 이미 내장된 스킬(skill-creator, code-review, simplify, security-review, plan 등)과 역할이 겹치는 스킬은 만들지 않는다.
- 대신 내장 스킬을 호출하거나 그 결과를 이어받는 방식으로 연동한다.
- 새 스킬을 설계할 때 먼저 "내장 스킬이 이미 이걸 하는가"를 확인한다.

### 3. 가볍게 만든다
- Superpowers 같은 기존 플러그인은 실사용 검증이 부족하고 무겁게 동작한다고 판단한다. 같은 길을 가지 않는다.
- 스킬 하나는 하나의 명확한 일을 한다. 항상 로드되는 내용은 최소로 하고, 상세 자료는 필요할 때만 읽는 `references/`로 분리한다.
- 훅과 자동화는 실제로 반복되는 문제에만 붙인다.

### 4. 내 판단이 우선이다
- 외부 프로젝트(`.ref/`)는 참고 대상이지 복제 대상이 아니다.
- 설계 결정은 이 문서의 목적과 원칙에 비추어 내린다.

## 스킬 채택 기준 (체크리스트)

세 게이트:
- [ ] **게이트 1** 트리거 eval을 통과했는가 (긍정·부정 케이스 모두)
- [ ] **게이트 2** 스킬 유/무 비교에서 품질이 확연히 향상되었는가
- [ ] **게이트 3** 기본 로드와 실행 토큰이 과하지 않은가 (과하면 라우팅으로 해결했는가)

부가 기준:
- [ ] 내장 스킬과 역할이 겹치지 않는가
- [ ] 위 네 가지 목적 중 하나 이상에 직접 기여하는가
- [ ] 반복적으로 쓰이는가 (한 번 쓰고 끝나는 것은 스킬로 만들지 않는다)
