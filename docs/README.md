# docs/

## 새 세션에서 읽는 순서

1. `principles.md` — **규칙의 유일한 원본.** 목적, 세 게이트, 설계 규칙, 자가 보완 루프, eval 규칙. 이것만 읽으면 규칙은 다 안다.
2. `ideas.md` — 스킬·플러그인 후보 백로그. 다음에 뭘 만들지 볼 때.
3. `study/` — 근거 자료. principles.md의 근거 약어(`MP`, `WK`, `DR`)가 가리키는 곳. 규칙의 **이유**가 궁금할 때만 연다.

## 파일 역할

| 파일 | 역할 | 쓰기 규칙 |
|---|---|---|
| `principles.md` | 규칙 원본 | 규칙 변경은 여기서만. 상태 표기(확정/미검증/가설)와 근거 링크 필수 |
| `ideas.md` | 백로그 | 아이디어 추가 자유. 채택 여부는 세 게이트로 |
| `study/mattpocock-skills.md` | 참고 저장소 스터디 (`MP`) | 증거 자료. 결론은 principles.md로 이관됨 |
| `study/obsidian-wiki-review.md` | 옵시디언 위키 검토, 규칙 후보 R1~R8 (`WK`) | 증거 자료. 후보의 채택 여부는 principles.md가 결정 |
| `study/deep-research-similar-cases.md` | 딥 리서치 + 독립 검증 (`DR`) | **7절 검증 결과가 기준.** 2~4절 원본은 왜곡이 있으므로 단독 인용 금지 |

## 스터디 노트 작성 규칙

- 저장소·주제 하나당 파일 하나. 파일명은 kebab-case.
- 노트는 **증거**다. "우리에게 적용할 것" 절은 후보 목록이지 규칙이 아니다. 규칙이 되려면 principles.md에 들어가야 한다.
- 외부 리서치(딥 리서치 등)는 1차 출처를 직접 읽는 독립 검증 절을 붙이기 전엔 미검증으로 취급.
- `study/deep-research-quality-skills.md` — 품질형 스킬 후보 딥 리서치 (2026-10-23)
- `study/deep-research-failure-driven.md` — 실패 빈도·결정적 도구 관점 딥 리서치, 리서치 1과 통합 우선순위 (2026-10-23)
