# 딥 리서치: 유사 사례·연구와 우리 규칙의 대조

- 실행일: 2026-10-22. `/deep-research` 워크플로(검색 5축 → 출처 22개 → 주장 110개 → 상위 25개를 3표 적대 검증 → 확인 18 / 기각 7).
- 질문: 우리와 같은 고민(경량 스킬 세트, eval 게이트, 자가 보완)을 한 사례와 연구를 찾아 세 게이트·규칙 후보 R1~R8과 비교.
- 신뢰도 표기: 각 항목의 투표(3-0 = 만장일치 확인, 2-1 = 다수 확인). 비동료심사 프리프린트가 많으므로 "방향"으로 읽고 "수치"는 인용 주의.

## 1. 한 줄 결론

세 게이트와 "결정적 제약은 훅, 규칙 파일은 사람 소유"는 1차 연구가 지지한다. 그러나 **전제 세 가지는 수정이 필요하다.**

1. 스킬은 얻는 만큼 **잃는다(회귀)**. 게이트 2는 "향상"이 아니라 "회귀 수"로 측정해야 변별력이 생긴다.
2. description은 호출되지 않아도 행동을 바꾼다(**삼투**). 게이트 3을 토큰 수로만 재면 이 비용을 놓친다.
3. "길면 안 따른다"는 근거가 약하다. 진짜 문제는 **세션 내 감쇠**이며, 해법은 짧게 쓰기가 아니라 훅이다.

## 2. 확인된 발견과 우리 규칙의 대조

### F1. 회귀세 (arXiv 2607.22520, 3-0) — 게이트 2 수정 근거
- 5,832회 실행에서 이득 553건 vs 회귀 324건. 이득의 59%가 상쇄됨. 18개 조건 중 회귀 0인 조건 없음.
- 최고 성능 라이브러리(skill-creator로 생성)는 이득이 가장 적었지만(10) 회귀가 가장 적어(2) 순이익 최대, 유일하게 p<.05.
- 독립 연구 2편(arXiv 2608.11888 스킬 유발 실패 307건, SkillRevise 2606.01139 31건 중 9건 회귀)이 같은 방향.
- **우리와의 차이**: 게이트 2는 "확연한 향상"만 본다. 이 데이터는 "회귀를 줄이는 것"이 채택 기준으로 더 변별력 있다고 말한다.
- 한계: 비동료심사, 시드 반복 없음, 보정 후 18셀 중 3셀만 유의.

### F2. description 삼투 (arXiv 2607.22520, 2-1) — 게이트 3 수정 근거
- 스킬이 호출되지 않아도 description이 컨텍스트에 있는 것만으로 결과가 바뀜. 회귀 중 OfficeQA 81건 중 14건, SpreadsheetBench 243건 중 70건이 이 메커니즘.
- 설정이 Claude Code와 동일(description 상시, 본문은 호출 시).
- **우리와의 차이**: 게이트 3이 "상시 로드 분량"만 재면 이 비용을 놓친다. `disable-model-invocation: true`면 description이 아예 로드되지 않으므로(F8) 삼투 비용도 0 → 토큰 우선 라우팅을 추가로 정당화.
- 주의: 삼투는 양방향. 저관여 스택에서는 무호출 이득이 삼투 회귀보다 많았음. "상시 description = 순손실"로 읽으면 과장.

### F3. 컨텍스트 파일은 성공률을 못 올리고 비용만 올린다 (arXiv 2602.11988, ICLR 2026, 3-0) — R3·R8 지지
- AGENTS.md/CLAUDE.md는 LLM 생성이든 사람 작성이든 성공률 변화 비유의(−0.5 / −2 / +2.4%p). 추론 비용은 +20% 이상(LLM 생성 기준 p<0.001).
- **LLM 생성 파일은 사람 작성본보다 유의하게 나쁨(p=0.038, 약 7%p).** → R3(에이전트 작성 로그는 지침으로 로드하지 않음)을 데이터로 뒷받침.
- 에이전트가 지시를 잘 따르기 때문에 **불필요한 요구가 과제를 어렵게 만든다**. 저자 권고: 최소 요구만.
- 반례 영역: 컷오프 이후 프레임워크 지식 주입(Vercel Next.js 16: 53%→79~100%)은 효과 큼. 즉 컨텍스트 파일은 "모르는 사실"에 쓰고 "행동 지침"에는 효과가 약하다.
- 기각된 표현(0-3): "평균적으로 성공률을 낮춘다". 쓰지 말 것. "무효(null)"이 맞다.

### F4. CLAUDE.md 길이·위치·구조는 준수율에 영향 없음 (arXiv 2605.10039, 3-0) — R5 근거 수정
- 1,650 세션/16,050 관측. 길이 25~500줄, 지시 위치, 단일/다중 파일, 충돌 지시 모두 보정 후 비유의(BF10=0.096).
- 저자가 "200줄 조언과 긴장 관계"라고 명시.
- **우리와의 차이**: R5 "200줄 미만"의 **준수율 근거는 이 범위에서 지지되지 않음**. 토큰 비용 근거(500줄≈5k 토큰)로는 유효.
- 한계: 종속변수가 `// @tracked` 주석 하나라는 사소한 지시, 단일 턴. 까다로운 규칙으로의 전이는 미확인.

### F5. 세션 내 감쇠 (arXiv 2605.10039, 2-1) — R1·R2 강화
- 함수를 하나 더 생성할 때마다 상시 지시 준수 확률 5.6% 하락(OR=0.944). 첫 누락 중앙값 4번째 함수.
- 저자 권고: 프로즈 대신 코드와 함께 이동하는 강제 수단(PreToolUse/PostToolUse/Stop 훅, 린터, CI).
- **우리와의 차이**: R2는 "2~3회 반복 위반 후 훅 승격"이다. 이 데이터는 **처음부터 결정적으로 검사 가능한 규칙은 프로즈 단계를 건너뛰고 바로 훅**으로 가야 한다고 말한다. 반복 임계는 "프로즈로 쓸지 말지"가 아니라 "애초에 규칙이 필요한지"를 판단하는 데만 쓴다.

### F6. ACE의 카운터 (arXiv 2510.04618, ICLR 2026, 3-0) — R4의 직접 선례
- 불릿마다 고유 ID + **helpful/harmful 두 카운터**. 전면 재작성 대신 델타 업데이트(카운터 증가·불릿 추가)를 비LLM 로직으로 결정적 병합. 임베딩 중복제거.
- **우리와의 차이**: (1) 우리는 "적중" 하나, ACE는 둘. 적중했지만 해로웠던 경우를 구분 못 하면 "0적중 제거"와 "해로운 규칙 제거"가 섞인다. (2) ACE는 카운터로 프루닝하지 않음. **"0적중 프루닝"은 선례 없는 우리 고유 규칙(미검증)**. (3) ACE는 사람 승인 없음. 2차 자료는 카운터가 오염을 완화하지만 제거는 못 하므로 사람 검토 권고.

### F7. 전면 재작성은 컨텍스트 붕괴 (arXiv 2510.04618, 2-1) — R2·R3 간접 지지
- Dynamic Cheatsheet 사례: 60스텝에 18,282토큰/정확도 66.7 → 다음 스텝 122토큰/57.1로 붕괴. 무적응 기준선(63.7)보다 나빠짐.
- Reflector가 약하거나 실행 피드백이 없으면 컨텍스트가 오염(FiNER 70.7→67.3).
- **우리에게**: 관찰 로그→규칙 승격 시 전면 재작성 금지, 델타만 허용. "사람 승인"은 논문의 해법이 아니라 연구자의 추론임을 명시.
- 한계: n=1 사례, 저자가 ACE 제안자.

### F8. Anthropic 공식 메커니즘 (3-0) — 우리 설계와 정합
- 3단 점진적 공개(name+description 상시 → 본문은 관련 판단 시 → 참조는 필요 시).
- 보완 사실: `disable-model-invocation: true` 스킬은 description이 컨텍스트에 **아예 없음**. description+when_to_use는 1,536자에서 잘림. 서브에이전트 preload 스킬은 SKILL.md 전체가 시작 시 주입.
- 참조 파일을 모델이 실제로 읽는지에 대한 **측정치는 공식 자료에 없음**. gstack의 "읽을 필요 없다고 오판" 우려는 증거 없는 상태.
- 기각(0-3): "트리거 결정은 오직 메타데이터만으로".

### F9. 배치 원칙 (codeminer42, Vercel, Anthropic memory 문서, 2-1) — R1 보완
- 상시 가이드라인(TDD, 컨벤션, "항상 X")은 CLAUDE.md, 온디맨드 절차는 스킬, 결정적 자동화는 훅. **"스킬은 가이드라인용이 아니다."**
- Vercel: AGENTS.md 100% vs 명시 지시 스킬 79% vs 기본 스킬 53%(=기준선, 56%는 스킬 미호출).
- **우리에게**: 스킬 세트에 "가이드라인성" 내용이 있으면 트리거 eval에서 저조할 것이 예측됨. 그런 내용은 CLAUDE.md(최소) 또는 훅/린터로.
- 기각(0-3): codeminer42의 구체 수치(6/33/66%)와 "Superpowers 효과는 SessionStart 훅 덕분" 귀인. 인용 금지, 방향성만.

### F10. 트리거 강제 훅 (scottspence.com, 2-1, 신뢰도 낮음)
- "관련 있으면 스킬 써라" 힌트 훅은 무훅과 차이 없음. 스킬별 YES/NO 강제 평가 훅이 should-not-fire 포함 세트에서 정확도 75%·거짓양성 0으로 가장 나음.
- 그러나 2026-03 이후 Claude Code가 UserPromptSubmit 훅을 무시하는 회귀 보고. 원 수치는 저자가 철회.
- Pilot Shell: "항상 발동하는 주입 훅은 모델이 무시하는 노이즈가 된다" → R8 정합.

### F11. 무거운 프레임워크의 측정 (arXiv 2604.05278, 2-1)
- Spec Kit류 파이프라인에 그라운딩 훅을 더해도 LLM-judge 품질 +0.15/5점(≈3%). 저자도 오버헤드 인정.
- **기각(0-3): "BMAD/Spec Kit/GSD는 독립 평가된 적이 없다."** 우리 principles.md의 "실사용 검증 부족" 표현은 **"측정된 효과가 작고 경량과의 직접 비교가 없다"**로 수정해야 한다.
- 무거운 것이 측정 가능하게 더 나았다는 증거는 이번 조사에서 없음.

## 3. 조사로 뒷받침되지 않은 우리 규칙 (반박된 것도 아님)

- `/skill-doctor`, `claude plugin eval`, IFScale, Context Rot: 검증 통과 자료 없음.
- "2~3회 반복 후 승격" 임계값, "0적중 프루닝": 어떤 선례에서도 직접 확인되지 않은 **우리 고유 규칙**. 미검증 표시 필요.
- 요청한 5축 중 "다른 개인/팀의 안티 프레임워크 스킬 세트 + 명시적 채택 기준" 사례와 "규칙을 썼지만 안 따름 / 자동 수집 거짓양성" 실패 사례는 **검증 통과 1차 자료가 없었다**. 옵시디언 위키의 claude-reflect #43, 이슈 #36296 등은 이번 적대 검증 대상에 들지 않았으므로 위키 쪽 신뢰도(medium)를 그대로 유지.

## 5. 열린 질문 (우리가 직접 측정하게 될 것)

- `disable-model-invocation: true`로 description을 빼면 삼투 비용이 실제로 0인가.
- 세션 내 감쇠(함수당 −5.6%)가 사소한 지시가 아닌 실질 규칙(테스트 우선 등)에서도 같은 크기인가. Stop 훅이 이를 복구하는가.
- helpful/harmful 카운터 + 사람 승인만으로 오염을 막는가. 사람 검토의 거짓양성(불필요한 규칙 승인)률은 측정된 사례 없음.
- 우리가 아는 경량 스킬 세트(mattpocock 등)에 대한 회귀 수 포함 독립 평가는 존재하지 않는다.
