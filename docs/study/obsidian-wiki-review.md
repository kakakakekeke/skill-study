# 옵시디언 위키 검토: 스킬 관련 문서와 현재 원칙의 대조

> 이 문서는 **증거 자료**다. R1~R8은 후보이며, 딥 리서치 독립 검증(`DR` 7절)을 거쳐 수정된 형태로 `docs/principles.md`에 반영됐다(근거 약어 `WK`). 규칙은 여기서 바꾸지 않는다.

- 검토일: 2026-10-22
- 대상: `llm-wiki` 볼트(skill-creator, 에이전트 자기개선 루프, 자기개선 루프 사례 research, 지침 파일 비대화, 에이전트 검증 루프, 에이전트 지침 파일, 컨텍스트 창 관리, 에이전트 토큰 최적화, Claude Code, LLM 코딩 가이드라인) + `Obsi/Clippings`(점진적 공개 vs 전체 인라인, 스킬 템플릿 컴파일, Superpowers 훅, gstack 3편)
- 대조 기준: `docs/principles.md`(세 게이트, 원칙 4개), `CLAUDE.md`

## 1. 결론

- **정면 모순은 없다.** 위키의 측정 증거(ETH AGENTS.md 평가, Context Rot, Anthropic 80% 삭제, claude-reflect 오탐 0%, Superpowers 1% 원칙)는 모두 현재 원칙(세 게이트, 경량, 내장 연동)을 **지지**한다.
- **긴장 1건**: "상세는 references/로 분리"(점진적 공개 일변도)와 gstack의 "반드시 실행될 제어는 인라인"이 충돌한다. 해소 방법은 아래 3절.
- **빈칸 7건**: 원칙이 침묵하고 있어 위키 근거로 정해야 할 규칙. 특히 목적 4(반복 오류 자가 보완)의 "어떻게"가 비어 있다. 위키는 이 부분에 가장 강한 근거를 갖고 있다.

## 2. 현재 원칙을 지지하는 위키 근거

| 현재 원칙 | 위키 근거 |
|---|---|
| 게이트 1: 과잉 트리거도 실패 | diagnosing-bugs 과잉 트리거 4명 보고(스터디 노트). Superpowers "1% 원칙"(확률 1%면 무조건 호출)은 정반대 설계이며 우리가 무겁다고 판단한 바로 그 원인 |
| 게이트 2: 스킬 유/무 비교 | skill-creator 판정 기준 "A skill that no longer beats the base model isn't broken, just unnecessary". 1인 환경 최소 조건은 고정 회귀 프롬프트 5~10개 |
| 게이트 3: 토큰 우선, 라우팅 허용 | 공식 문서: 부작용 있는 워크플로는 `disable-model-invocation: true`. ETH: 컨텍스트 파일은 성공률 거의 안 올리고 비용 +20%. Chroma: 300토큰 집중 프롬프트가 113k보다 높은 점수 |
| 경량, 상시 로드 최소 | 지침 파일 비대화: 400줄 CLAUDE.md에서 MUST도 50% 무시. 모순 지시는 "may pick one arbitrarily" |
| 내장 스킬 연동 | Claude Code 자기개선 기능 표(`/insights`, `/doctor prompt-audit`, `/skill-doctor`, `claude plugin eval`, skill-creator)가 이미 분석·제안을 덮는다. 만들 것은 그 사이의 빈칸뿐 |

## 3. 긴장: 점진적 공개 vs 인라인

**현재**: "SKILL.md 지침은 간결하게, 긴 자료는 references/로 분리"(CLAUDE.md), "항상 로드되는 분량 최소화"(principles).

**위키 반론**(gstack 클리핑): 점진적 공개는 에이전트가 "읽을 필요 없다"고 오판하면 누락된다. 안전장치는 에이전트가 참조 문서를 읽기도 전에 셸 명령을 실행하면 무력화된다. gstack은 그래서 제어 프로토콜을 전부 인라인했고, mattpocock도 "모든 분기가 필요한 것은 인라인"이라고 했다.

**판정**: 모순이 아니라 원칙의 **적용 범위가 미지정**된 것이다. 두 소스가 같은 결론을 가리킨다.

- 도메인 지식·긴 참조 → references/ (현행 유지)
- 모든 분기가 반드시 거치는 짧은 제어 → SKILL.md 본문 인라인
- 결정적으로 지켜져야 하는 것(파괴 명령 차단, 검사 통과 전 종료 금지) → **문서가 아니라 훅**. gstack의 "인라인"은 훅 없는 호스트(Codex)용 폴백이었다. Claude Code 전용인 우리는 훅을 쓰면 되고, 그러면 토큰 우선 원칙과도 충돌하지 않는다.

→ 규칙 후보 R1.

## 4. 빈칸: 정해야 할 규칙 후보

### R1. 배치 규칙 (3절의 해소)
반드시 지켜야 하는 것은 훅, 모든 분기가 거치는 짧은 제어는 본문, 나머지는 references/. "지시로 강제"는 선택지가 아니다(CLAUDE.md·메모리는 "context, not enforced configuration").

### R2. 자가 보완의 구조: 감지는 자동, 승격은 사람, 반복은 훅
목적 4가 현재 "어떻게"가 없다. 위키의 핵심 결론: 병목은 쓰기가 아니라 **선별과 적용**이다. 교정을 적는 루프는 10여 개 플러그인이 이미 했고 효과 측정은 하나도 없다. 적어도 행동이 안 바뀐 사례(이슈 #36296: 같은 규칙 메모리 6개에도 재발)가 공식 저장소에 있다.
- 신호 감지: **고정 트리거**(세션 종료, Stop 훅)로. 판단 의존 캡처는 60세션 중 2회 발동, regex 캡처는 625건 중 적중 0%.
- 승격 임계: 한 세션 교정을 바로 규칙화하지 않는다. **2~3회 반복** 관찰 후 사람 승인.
- 반복 위반(승격 후에도 재발)은 지시가 아니라 **훅/린터로 승격**. 이것이 "적어도 안 바뀜" 문제의 유일한 구조적 해법.
- 자동 **적용**은 하지 않는다(리뷰형). 사용자가 "auto-hook에 당했다"는 보고가 retro 문서에도 있다.

### R3. 역할 분리: 규칙 파일은 사람 소유, 관찰 파일은 에이전트 소유
에이전트가 쓰는 파일이 곧 에이전트가 읽는 지시 파일이면 프롬프트 인젝션이 영구화된다(Akamai 사례). 2026년 상반기 이후 신규 프로젝트는 CLAUDE.md 직접 편집을 피하고 별도 파일·DB로 옮겼다. Anthropic도 `#` 단축키를 제거했다.
- CLAUDE.md, SKILL.md 본문: 사람이 쓰고 승인
- 관찰 로그(어떤 오류가 몇 번): 에이전트가 쓰되, 그 파일은 지시로 로드하지 않는다

### R4. 규칙마다 출처 실패와 카운터를 붙인다
ACE 불릿의 저비용 버전: "한 줄 규칙 + 어떤 실패에서 나왔는지 + 적중/해악 횟수". retro의 약점(자기가 만든 검사를 감사 못 함, 규칙이 영원히 쌓임)을 이것으로 막는다. 카운터가 0인 규칙은 제거 후보.

### R5. 크기 상한과 정기 감사
파일당 200줄 미만. 줄마다 "지우면 실수가 생기는가". `/doctor prompt-audit`로 모순·stale 참조 제거. **우리 CLAUDE.md 자체에도 적용**한다. 지금은 30줄대지만 원칙을 더 넣으면 바로 비대화 경로에 들어간다. 원칙은 principles.md에, CLAUDE.md는 포인터만.

### R6. eval 실행 규칙
- **형식**: skill-creator의 `evals/evals.json`을 표준으로. `claude plugin eval`과 형식이 호환되지 않으므로 하나를 골라야 한다. 우리는 CLAUDE.md에서 이미 skill-creator를 지정했다.
- **반복 횟수**: 단일 실행 비교 금지. skill-creator 기본(쿼리당 3회, mean±stddev)을 최소로. skills-autoresearch는 judge 노이즈로 9회 반복 후 정체했다.
- **트리거 eval**: should / should-not 쿼리 약 20개, train/test 분리(60/40). 과적합 방지.
- **비변별 assertion**: 스킬 유무와 무관하게 통과하는 assertion은 삭제. 게이트 2의 "확연한"을 이것으로 조작화한다.
- **증거 요구**: 성공 주장 대신 테스트 출력·실행 명령·결과를 보이게 한다(검증 루프 문서). grader에도 evidence 필수.
- **토큰 측정 도구**: `/skill-doctor`(스킬별 컨텍스트 비용·호출 빈도)를 게이트 3의 공식 측정 수단으로.

### R7. 결정적 작업은 scripts/로, LLM을 파서로 쓰지 않는다
토큰 최적화 포스트모템: 정제·차분 계산은 로컬 스크립트가 끝내고 LLM에는 판단에 필요한 수 KB만 준다. 큰 도구 출력은 수십 줄 이내. skill-creator 원칙("반복 작업은 scripts/로")과 같다. 현재 CLAUDE.md의 "스크립트는 scripts/에"는 위치만 말하고 **언제** 스크립트로 가야 하는지가 없다.

### R8. 상시 주입 금지
Superpowers는 SessionStart 훅으로 매 세션 "스킬 탐색기"를 최상단에 주입하고 "1% 원칙"으로 호출을 강제한다. 지침 파일 비대화 증거와 정반대 방향이다. 우리 플러그인은 SessionStart에 아무것도 주입하지 않거나, 주입하더라도 게이트 3 측정을 통과한 한 줄 포인터로 제한한다.

## 5. 현재 문서 안의 내부 불일치 (위키와 무관)

- principles.md 원칙 1 "효과가 입증되지 않은 지침은 넣지 않는다"와 CLAUDE.md의 "SKILL.md 지침은 간결하게"가 **각각 다른 파일에서 같은 뜻을 반복**한다. R5에 따라 CLAUDE.md는 포인터로 줄이고 내용은 principles.md 한 곳에 둔다.
- 스터디 노트 8절에서 이미 "감지는 자동, 처방은 사람 승인"을 결론냈지만 principles.md에는 반영되지 않았다. R2로 승격하면 해소된다.

## 6. 위키에서 가져오지 않는 것

- gstack의 템플릿 컴파일(`SKILL.md.tmpl` → 빌드). 50개 스킬에 공통 preamble을 넣기 위한 장치다. 우리는 스킬 수가 적고 상시 주입을 하지 않으므로 불필요. 다만 "스킬 간 공통 문구는 복붙하지 말고 model-invoked 참조 스킬 하나로"는 mattpocock 방식으로 해결한다.
- gstack의 `/plan-tune`(질문 자동 결정 훅). 그릴링에 네이티브 질문 UI를 쓰지 않는다는 mattpocock의 결정과 우리의 "사람 승인" 원칙 양쪽과 어긋난다.
- 학술 메커니즘(ACE, GEPA, DGM)의 홀드아웃·파레토. 수십~수천 개 평가 인스턴스를 전제한다. 1인 환경에서는 R2의 "반복 임계 + 사람 승인"이 그 자리를 대신한다는 것이 위키의 결론이다.

## 7. 위키 쪽에 남길 메모

- 위키 `skill-creator` 문서의 "미열람: grader.md·analyzer.md·comparator.md 원문" — 우리 eval 설계(R6)에 직접 필요하므로 다음 스터디 대상.
- 위키 열린 질문 "루프 자체의 with/without A/B는 존재하는가"는 아직 없음. 우리 프로젝트가 자가 보완 스킬을 만들면 그 측정을 직접 하게 된다.
